# ボス獲得型ボスバトル 企画書

Nov 6, 2026 · @Miyamoto

## 概要

倒したボスを砕いて手に入れ、次の戦いではそのボス自身として戦える、三人称3DのPvEボスバトルゲーム。

| 項目 | 内容 |
| --- | --- |
| エンジン | Unreal Engine 5.8 |
| ジャンル | 3D・三人称・PvEボスバトル |
| プレイ人数 | 通常ボス：シングル / レイドボス：マルチ |
| 参考作品 | ガイストクラッシャー（倒した敵を砕いて獲得する仕組み） |
| 制作形態 | 個人制作 |

- ボスは複数体登場し、通常ボスはすべてプレイアブルになる
- レイドボスは獲得できない、より強力なボスとしてマルチで挑む

## 面白さの核

派手なバトルに加えて、「あんなに強かったボスを、自分が使いこなせるようになる」ことがこのゲームの根幹の面白さ。報酬は素材ではなく、強敵そのものになる体験。

### 着想

- モンハンなどの「敵を倒して素材を集め、防具を作る」作業のような時間をなくしたい
- 素材を集めるのではなく「ボスになっちゃえ」という発想で、ガイストクラッシャーを参考にした
- 妖怪ウォッチ初代の最強ラスボス「黒鬼」が、妖怪ウォッチ2で使えるようになった時の興奮を目指す
- 前提として、ボスが強い、またはかっこよくなければ成立しない

### 核を守るための方針

| 方針 | 内容 |
| --- | --- |
| レベル上げを作業にしない | 経験値は普通にボスと戦えば自然に溜まる量にする。砕く成否はレベルだけでなく腕でも縮められるようにし、育成を「使いこなしていく過程」に感じさせる |
| 仲間になっても弱くしない（敵の時の技はすべて使える） | 敵の時に使っていた技は、プレイアブル時もすべてそのまま使える（プレイアブル用に別の技セットは作らない）。自分を苦しめた必殺技を同じ迫力で撃て、バランスはボス同士で取る。技が多い場合はコンボ・スキルボタン・ゲージ技に整理し、溜めが長い技や広範囲の技は削らずゲージやクールダウンで制御する。第二形態の技は「覚醒モード」としてゲージ解放で使えるようにする |
| かっこよさをモデル以外でも出す | シルエットが一目で分かるデザイン、アニメーションの重さ・溜め、VFX（GameplayCue）で強さを見せる |
| 見せ場のカメラ演出を凝る | 登場演出、必殺技、砕いて獲得した瞬間、初めてそのボスで必殺技を撃つ瞬間を最大の見せ場にする |

## コアループ

&#91;embedded content: コアループ · 倒す→砕く→獲得→育成\]

砕けるかどうかはキャラクターのレベル次第なので、獲得したボスを育てることが、次のより強いボスを獲得する鍵になる。

## ゲームシステム詳細

獲得条件は「制限時間内に塊を砕くこと」だけで、確率要素はない。砕く力はキャラクターのレベルに依存する。

### 通常ボス

- シングルプレイで挑む
- 体格はプレイヤーと統一する（カメラ・当たり判定・アリーナを共通化できる）
- 複数体用意し、倒して砕けば全員プレイアブルになる

### 砕くフェーズ

- ボスを倒すとボスが塊になる
- 制限時間内に塊を壊せたら、そのボスを確定で獲得
- 時間内に壊せなければ獲得できない

### プレイアブル化

- 獲得したボスに「なる」形で操作する（召喚・装備ではない）
- 以降の戦闘でそのボスを使って戦える

### 成長（レベル）

- キャラクターごとに経験値を付与し、個別にレベルアップする
- レベルを上げることで、より強いボスの塊を時間内に砕けるようになる

### レイドボス

- 獲得できない、通常ボスより強力なボス
- マルチプレイで倒す
- ドラゴンなど、プレイヤーと体格差のあるモデルにする

## 技術構成とクラス設計

同じボスのクラスを、敵の時はAIController、プレイアブルの時はPlayerControllerがPossessするだけで切り替える。技はGameplayAbilityとして作り、AIとプレイヤーで共有する。

| 技術 | 使用対象 | 役割 |
| --- | --- | --- |
| GAS | プレイヤー・ボス | 技、ステータス、ダメージ、レベル、ネットワーク |
| Behavior Tree | ボス（AI時） | 行動判断。サーバーでのみ動作し、結果はキャラ移動とGASの複製で伝わる |

### 主なクラス

| クラス | 内容 |
| --- | --- |
| ABossCharacterBase | ASC・AttributeSetを持つ通常ボス共通クラス。ASCはキャラクター側に持たせる |
| UBossDefinition（DataAsset） | メッシュ、所持GA一覧、BT、InputMappingContext、レベル別ステータスのCurveTable |
| ARaidBossCharacter | レイドボス用。GASの仕組みは共有し、Possession切り替えは考慮しない。部位ごとの当たり判定を持つ |
| 塊Actor | HPを持つ砕く対象。制限時間はゲームモード側で管理 |

### キャラクター切り替え

アビリティを付け替えるのではなく、ボスのポーンごと乗り換える。

1. 切り替え先のボスをSpawnし、BossDefinitionを渡す
2. PlayerControllerが今のポーンをUnPossessし、新しいポーンをPossess
3. PossessedByで InitAbilityActorInfo、GA付与、レベル別ステータスのGE適用
4. PlayerControllerのOnPossessかPawnClientRestartでInputMappingContextを差し替え
5. 古いポーンをDestroy

回避・ロックオンなどプレイヤー操作時だけの共通技は、PlayerControllerがPossessした時だけ追加で付与する。

### 技の発動

- プレイヤー：Enhanced Input → InputTag → GA
- AI：BTタスク → タグ指定またはGameplayEvent → 同じGA

### レベル

- GEのLevelとCurveTableでステータスを伸ばす
- 「砕く力」もAttributeとして持たせる
- キャラクターごとの経験値とレベルはSaveGameに保存する

## 設計上の課題と対策

| 課題 | 対策案 |
| --- | --- |
| レベルだけで砕けるか決まると作業感が出る | 塊に弱点を出す、コンボで砕く量が増えるなど、腕で縮められる要素を入れる |
| 砕けなかった理由が分かりにくい | 推奨レベルなど、砕けるかの目安を表示する |
| 体格が同じだとボスらしさが出にくい | 技の派手さ、エフェクト（GameplayCue）、専用アリーナ、フェーズ移行の演出で強さを見せる |
| AI用に作った技を人間が操作して気持ちいいか | 同じGAを使いつつ、プレイアブル時の操作感を個別に調整する |
| 巨大なレイドボスはカプセル1つの当たり判定だと破綻しやすい | 頭・翼・尻尾など部位ごとの当たり判定を持たせる |

- 未決定：最初の1体のボス（技数・プレイアブル時の操作感）
- 未決定：ゲームタイトル

## 開発ロードマップと学習項目

まずボス1体・シングル・プレイアブル化までを縦に通し、ループが楽しいと確認してから広げる。

### 開発の順番

1. ボス1体の通常攻撃とコンボを、プレイヤーとAIの両方から出せるようにする
2. 倒す → 砕く → 獲得 → プレイアブル化のループを1体で通す
3. キャラクターごとの経験値・レベルとセーブを入れる
4. 通常ボスを増やす
5. レイドボスとネットワーク（マルチ）を作る

### GASで学ぶ項目（優先順）

1. 基本の5要素：ASC、AttributeSet、GameplayAbility、GameplayEffect、GameplayTag
2. GameplayEffect：Instant / Duration / Infinite、ダメージ計算（ExecutionCalculation・MMC）、CurveTable＋Levelのスケーリング
3. 発動の入口：Enhanced Input＋InputTag、BTタスクからのタグ・GameplayEvent発動
4. AbilityTask：PlayMontageAndWait、WaitGameplayEvent、WaitInputPress。コンボはこれ＋モンタージュのセクション＋タグで組む
5. タグによる状態制御：クールダウン、コスト、ブロック／キャンセル、怯み・スタン
6. GameplayCue：ヒットエフェクトや技の演出
7. Possession切り替え時の初期化：InitAbilityActorInfo、能力付与、入力の再設定
8. ネットワーク（レイド段階で）：レプリケーションモード、予測（LocalPredicted）、サーバー専用処理
